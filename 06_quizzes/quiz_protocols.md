## Detailed Explanations

**Q1 -- Answer: B**

Asynchronous means there is no shared clock signal between the communicating parties. UART uses a start bit (falling edge) to signal the beginning of a frame; the receiver then samples each subsequent bit at intervals equal to 1/baud_rate using its own oscillator. Both sides must be configured to the same baud rate in advance. Option A describes full-duplex operation, which UART supports but is not the definition of asynchronous. Option C is wrong; baud rate is fixed per configuration. Option D describes a multi-drop bus, not asynchronous communication.

---

**Q2 -- Answer: B**

SPI is a synchronous, full-duplex, master-driven protocol. The master always generates SCLK. CS (Chip Select) is active low: the master pulls it low to select the target slave before the clock starts. MOSI carries data from master to slave; MISO carries data from slave to master simultaneously. Option A incorrectly states the clock is generated by the slave and CS is active high. Option C is wrong; MOSI and MISO are unidirectional and the master always drives the clock. Option D correctly states signal directions but incorrectly states the clock is from the slave.

---

**Q3 -- Answer: B**

The 7-bit address space provides 128 codes (0x00 -- 0x7F). However, the I2C specification reserves several address ranges: 0x00 (general call), 0x01--0x03 (CBUS and other reserved), 0x04--0x07 (future use), 0x78--0x7B (10-bit addressing extension), and 0x7C--0x7F (future use). This leaves 112 usable addresses for general devices. Option A ignores the reserved addresses. Option C is wrong; the R/W bit is not part of the address -- it selects direction for the current transaction, and both read and write transactions address the same device. Option D describes 10-bit addressing mode, which is an extension not universally supported by all devices.

---

**Q4 -- Answer: C**

CAN uses a wired-AND bus topology where a dominant bit (driven by any node as logic 0, pulling the differential bus to CANH=3.5V, CANL=1.5V) overwrites a recessive bit (logic 1, bus floats to CANH=CANL=2.5V). When two nodes transmit simultaneously, each monitors the bus while driving. If a node transmits a recessive 1 but reads a dominant 0 on the bus, it knows it has lost arbitration and immediately stops transmitting without corrupting the winning frame. The winner, transmitting a 1 that survives (or a 0 that dominates), never even detects a collision. Lower identifier values win because they contain more dominant (0) bits in earlier positions. Option A describes token ring. Option B describes Ethernet CSMA/CD, where collisions are destructive. Option D describes a master-slave bus like I2C or USB.

---

**Q5 -- Answer: B**

USB 2.0 defines three speed modes: Low Speed (1.5 Mbps, for keyboards and mice), Full Speed (12 Mbps, the original USB 1.1 speed), and High Speed (480 Mbps). USB 3.x introduces SuperSpeed (5 Gbps), SuperSpeed+ (10 Gbps), and higher. A "Full Speed" device operates at 12 Mbps. Option A is Low Speed. Option C is High Speed. Option D is SuperSpeed (USB 3.2 Gen 1).

---

**Q6 -- Answer: C**

CPOL defines the idle state of the clock: CPOL=1 means the clock idles high. CPHA defines which clock edge is used to sample data: CPHA=1 means data is sampled on the second clock edge. When CPOL=1, the clock transitions from idle-high to low (falling edge) as the first edge, and back to high (rising edge) as the second edge. So with CPHA=1, data is sampled on the rising edge (second edge). Mode 3 (CPOL=1, CPHA=1): idle high, sample on rising edge. Option A describes Mode 0 (CPOL=0, CPHA=0): idle low, sample on rising edge. Option B describes Mode 2 (CPOL=1, CPHA=0): idle high, sample on falling edge (first edge). Option D describes Mode 1 (CPOL=0, CPHA=1): idle low, sample on falling edge (second edge).

---

**Q7 -- Answer: B**

Clock stretching is a slave-to-master flow control mechanism. The master releases SCL high after the low period; a slow slave can hold SCL low before the master releases it, delaying the rising edge. The master must monitor SCL and wait until SCL actually goes high before proceeding. This gives the slave extra processing time (for example, to complete an ADC conversion or access internal EEPROM). Not all I2C masters support clock stretching -- this is a common compatibility issue. Option A is wrong; the master controls frequency in normal operation. Option C describes a different timing concept (there is no single-bit pause for ACK -- the ACK is a normal bit period). Option D is wrong; clock stretching is a master-slave mechanism, not a multi-master one.

---

**Q8 -- Answer: B**

CAN has no concept of a destination address. Each message has an identifier (11-bit in standard frame, 29-bit in extended frame) that simultaneously encodes the message priority and the message type or content. Every node on the bus receives every frame and decides independently whether to process it based on its local filter configuration. The identifier also determines bus priority during arbitration: lower numeric ID wins. Option A is wrong; there is no destination address field. Option C is wrong; while the identifier often implicitly identifies the source node, this is a system design convention, not a protocol-level source address field. Option D is wrong; the DLC (Data Length Code) field specifies the data length, not the identifier.

---

**Q9 -- Answer: B**

IP fragmentation is the mechanism that allows a large datagram to be sent over a network with a smaller MTU. The IP layer at the sender breaks the datagram into multiple IP packets, each with an IP header containing a Fragment Offset field and a More Fragments (MF) flag. The destination IP layer reassembles the fragments before delivering the data to TCP or UDP. On embedded systems this is important: IPv4 requires all hosts to reassemble fragments; routers may fragment datagrams when forwarding to a lower-MTU network. Option A is wrong; IP does not discard large datagrams (unless the DF -- Don't Fragment -- flag is set). Option C is wrong; jumbo frames are an Ethernet switch configuration that must be negotiated at the link layer and is not automatically used by the IP layer. Option D is incorrect; standard Ethernet frames do not have non-standard extended headers for this purpose.

---

**Q10 -- Answer: C**

USB control transfers use a bidirectional default pipe (Endpoint 0) and are mandatory for all USB devices. They are used during enumeration (GET_DESCRIPTOR, SET_ADDRESS, SET_CONFIGURATION) and for class-specific requests (e.g., SET_REPORT for HID, SET_LINE_CODING for CDC). Control transfers have a defined setup-data-status phase structure and guarantee delivery via ACK/NAK/STALL. Option A describes isochronous transfers (used for USB audio and video). Option B describes bulk transfers (used for mass storage, printers, CDC data). Option D describes interrupt transfers (used for HID devices, though the term "interrupt" in USB refers to bounded polling latency, not hardware interrupts).

---

**Q11 -- Answer: B**

I2C multi-master arbitration exploits the wired-AND property of the open-drain SDA line. Both masters can read the actual state of SDA even while transmitting. Each master compares what it wrote to what it reads: if it wrote a 1 (released SDA) but reads a 0 (another master is pulling SDA low), it has lost arbitration and stops immediately. The winning master detects no discrepancy and continues transmitting the entire message without interruption. Arbitration is resolved bit-by-bit using the data being sent, similar to CAN. Option A describes an Ethernet collision recovery model, which is inappropriate for I2C. Option C is wrong; both start conditions may begin simultaneously and the arbitration happens during address and data bits. Option D is not part of the I2C specification.

---

**Q12 -- Answer: C**

Two 120-ohm termination resistors in parallel produce a total bus impedance of 60 ohms. The CAN transmitter is designed to drive a 60-ohm load (two 120-ohm resistors at each end), and the resulting differential voltage is nominally 2 V. If an extra 120-ohm resistor is added (three total), the parallel impedance drops to 40 ohms, increasing the current drawn from the transceiver. This can cause the driver to saturate and reduce the achievable voltage swing. Option A (baud rate vs. cable length) affects signal propagation delays and bit timing but would not systematically reduce the steady-state differential voltage. Option B describes the opposite problem (missing termination): with one 120-ohm terminator instead of two, the bus impedance is 120 ohms, which would increase the differential voltage swing above nominal, not reduce it. Option D is a plausible cause but is a separate, independent failure mode that the question is not describing.

---

**Q13 -- Answer: B**

For a long transmission line, proper termination is required at both ends to prevent signal reflections. At 1 Mbps over 200 m, the propagation delay is approximately 1 microsecond (0.2 m/ns for typical cable), and the bit time is 1 microsecond. The ratio of propagation delay to bit time is approximately 1, meaning reflections from an unterminated far end would arrive close to the next bit boundary, causing significant inter-symbol interference. Both ends of the RS-485 bus must be terminated with resistors matching the characteristic impedance (120 ohms). Additionally, bias resistors (pull-up on A, pull-down on B) are needed to keep the bus in a defined idle state when no driver is active, preventing false start conditions from noise on a floating bus. Option A is wrong; single-end termination leaves reflections from the far end. Option C is wrong; 60 ohms would over-terminate a 120-ohm line. Option D is wrong; the propagation delay is comparable to the bit time, so reflections are a real problem.

---

**Q14 -- Answer: B**

In USB 2.0, the host initiates all transactions. For a bulk IN transfer, the host sends an IN token packet to the device. If the device has data, it responds with a DATA0 or DATA1 packet, and the host sends ACK. If the device has no data ready, it responds with NAK. The host retries in a later microframe (125 us for High Speed). This polling is automatic and continuous; the host does not need notification from the device. Option A describes a successful bulk IN transaction. Option C is wrong; holding D+ and D- low is a bus reset or chirp condition, not a NAK. Option D describes an interrupt transfer mechanism, not a bulk transfer mechanism.

---

**Q15 -- Answer: C**

When a UDP receiver is slower than the sender, the socket's receive buffer (maintained by the TCP/IP stack or OS in memory) fills with unread datagrams. When the buffer is full, new incoming datagrams are silently dropped at the socket layer -- UDP has no flow control and no retransmission. The MAC and PHY continue to receive frames without error, and the MAC ring buffer is not involved in socket-layer buffering, so those layers report no issues. The fix is to increase the socket receive buffer size (`SO_RCVBUF`), reduce sender rate, or process datagrams faster in the application (use a dedicated high-priority receive task). Option A is wrong; UDP checksum failures cause the stack to discard the packet, but this would be visible as checksum error counters, and byte-order issues affect data interpretation, not delivery. Option B is wrong; TTL is decremented by routers, and packets on a local LAN or arriving at the destination do not expire in transit. Option D is a plausible cause of silent drops, but the question specifies the PHY shows no errors, implying frames are received correctly and it is an application-layer consumption issue.
